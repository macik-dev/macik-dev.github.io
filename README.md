# Курс по Roblox Studio — сайт с материалами

Сайт-каталог уроков по Roblox Studio и языку Luau для детей 10–15 лет.
Уроки пишутся текстом в обычных файлах, а меню, главная страница, оглавление,
ссылки «предыдущий → следующий» и карта сайта собираются сами.

Эта инструкция написана для человека, который не программирует. Команды нужно
набирать в терминале — это чёрное окно, где текст вводится с клавиатуры.

## Что нужно установить один раз

1. **Node.js** — [nodejs.org](https://nodejs.org), версия 20 или новее. Берите
   кнопку **LTS**. Это то, на чём собирается сайт.
2. **Git** — [git-scm.com](https://git-scm.com). Через него сайт попадает в интернет.
3. **Редактор текста** — подойдёт [Visual Studio Code](https://code.visualstudio.com).
   Можно и «Блокнот», но в редакторе удобнее.

Проверить, что всё встало: откройте терминал и наберите

```
node -v
git -v
```

Обе команды должны напечатать номер версии. Если пишет «не является внутренней
или внешней командой» — программа не установилась, попробуйте ещё раз и
перезапустите терминал.

## Первый запуск

Один раз, в папке проекта:

```
npm install
```

Команда скачает всё нужное. Это займёт минуту-другую и больше не понадобится.

Дальше, каждый раз когда садитесь работать:

```
npm run dev
```

В терминале появится адрес — обычно `http://localhost:4321/`. Откройте его в
браузере: это ваш сайт, но пока только на вашем компьютере. Пока эта команда
работает, страница обновляется сама при каждом сохранении файла — правите текст
урока, нажимаете «сохранить», смотрите результат.

Чтобы остановить — нажмите в терминале **Ctrl + C**.

## Как добавить урок

Одна команда и один файл. Больше ничего трогать не нужно.

```
npm run new-lesson
```

Скрипт задаст четыре вопроса:

| Вопрос | Что отвечать |
|---|---|
| Название урока | Так урок будет называться в меню. Например: `Циклы: for и while` |
| Раздел | Номер из списка. Просто нажмите Enter, если раздел один |
| Номер по порядку | Предлагается первый свободный. Обычно достаточно нажать Enter |
| Адрес урока | Предлагается сам, из названия. Обычно достаточно нажать Enter |

После этого появится файл `src/content/lessons/адрес-урока.mdx` с заполненной
шапкой и скелетом всех секций. Откройте его в редакторе и пишите.

Урок сразу помечен `draft: true` — это значит **черновик**: на сайте его нет,
он виден только у вас при `npm run dev`. Когда урок готов, поменяйте в шапке
файла `draft: true` на `draft: false`.

### Убрать, переставить, переименовать

- **Убрать урок с сайта** — поставить `draft: true` или удалить файл.
- **Переставить уроки** — поменять число в поле `order`. Меньше число — раньше урок.
- **Новый раздел** — дописать строчку в файле `src/content/sections.mjs`.

Меню, главная и ссылки «предыдущий → следующий» пересоберутся сами.

## Из чего собирается урок

Файл урока состоит из двух частей: **шапки** между двумя `---` в самом верху
и **текста** под ней.

### Шапка

```yaml
---
title: 'Переменная, которая считает саму себя'   # название в меню
slug: 'sostavnye-operatory'                       # адрес: /lessons/sostavnye-operatory/
order: 1                                          # порядок среди уроков
section: 'osnovy'                                 # раздел
summary: 'О чём урок. Одно-два предложения.'      # вступление и подпись на карточке
draft: false                                      # true = черновик, на сайте нет
---
```

Эти шесть полей обязательны. Если пропустить или ошибиться в типе, сборка
остановится и напишет по-русски, в каком файле и какое поле чинить.

Необязательные поля: `headline` (заголовок на самой странице, знак `|` делает
перенос строки), `eyebrow` (строчка над заголовком), `readingMinutes`, `chips`
(дополнительные метки), `tags`, `updated`, `prerequisites`.

### Текст

Обычный текст с разметкой Markdown плюс готовые блоки:

````mdx
<Section title="Короткая запись" sub="Тот же смысл, вдвое меньше букв">

Обычный текст, **жирный**, `код внутри строки`.

```luau title="Script"
local score = 0
score += 10
```
<Output>10</Output>

<Note kind="warn" title="Осторожно">
Место, где обычно путаются.
</Note>

</Section>
````

Все блоки — `Note`, `Task`, `Trainer`, `Steps`, `VarBox`, таблицы — показаны на
служебной странице **`/lessons/demo-komponenty/`**. Запустите `npm run dev`,
откройте её и держите рядом: под каждым блоком написано, как он пишется.
На опубликованном сайте этой страницы нет.

### Что считается само

Не пишите руками — оно посчитается на сборке:

- номера секций (`01`, `02`) и оглавление;
- номера заданий (`А1`, `А2`, `Б1`) — буква берётся из группы;
- счётчик «12 заданий» в заголовке группы;
- метки в шапке урока: время чтения, сколько тренажёров, устных и письменных заданий;
- подпись у спойлера: «Показать ответ» у устного задания, «Показать решение» у письменного.

## Как опубликовать

```
npm run publish
```

Одна команда делает всё: проверяет, не попал ли в файлы пароль или токен,
проверяет уроки, собирает сайт начисто, сохраняет изменения и отправляет их на
GitHub. Дальше GitHub соберёт сайт сам — это занимает 1–2 минуты.

Можно добавить пояснение, что именно поменялось:

```
npm run publish -- "добавил урок про циклы"
```

Если на любом шаге что-то не так, скрипт остановится и напишет, что чинить.
Наполовину опубликовать сайт он не может.

Посмотреть, как идёт сборка на стороне GitHub, можно на вкладке **Actions**
в репозитории.

## Первая публикация: настройка GitHub

Это делается один раз.

### 1. Создать репозиторий

На [github.com](https://github.com) нажмите **New repository**. Назовите его
**ровно так**: `ВАШ-ЛОГИН.github.io` — например, `ivanov.github.io`.
Тип — **Public**. Ничего внутрь не добавляйте (ни README, ни .gitignore).

### 2. Вписать адрес сайта

Откройте файл **`site.config.mjs`** и поменяйте одну строчку:

```js
export const SITE = 'https://ivanov.github.io';
```

Это единственное место, где указан адрес. Всё остальное — карта сайта, ссылки,
настройки редактора — считается отсюда.

### 3. Связать папку с репозиторием

В терминале, в папке проекта:

```
git init
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/ВАШ-ЛОГИН.github.io.git
```

И один раз представьтесь git'у:

```
git config --global user.name "Имя Фамилия"
git config --global user.email "почта@example.com"
```

### 4. Включить GitHub Pages

В репозитории: **Settings → Pages → Build and deployment → Source** выберите
**GitHub Actions**. Не «Deploy from a branch», а именно **GitHub Actions**.

### 5. Опубликовать

```
npm run publish
```

Через пару минут сайт будет доступен по адресу `https://ВАШ-ЛОГИН.github.io/`.

## Визуальный редактор

Если править текст в редакторе кода неудобно, есть редактор с полями и
подсказками — Sveltia CMS.

1. Запустите `npm run dev`.
2. Откройте **`http://localhost:4321/admin/`**.
3. Нажмите **Work with Local Repository** и выберите папку проекта.
4. Браузер спросит разрешение на доступ к папке — разрешите.

Дальше уроки редактируются как в обычной форме: поля шапки с подсказками,
текст урока отдельным окном. Правки сохраняются прямо в файлы `.mdx` на диске.
Чтобы они попали на сайт, потом всё равно нужно выполнить `npm run publish`.

**Что важно знать:**

- Редактор работает **только в Chrome или Edge**. В Firefox и Safari нет
  того способа доступа к файлам, который ему нужен.
- Текст урока редактируется **как есть**, без оформления «как в Ворде». Так
  сделано намеренно: урок состоит из блоков вроде `<Section>` и `<Task>`, а
  редактор с кнопками «жирный/курсив» такие блоки ломает.
- Страницы `/admin/` **нет на опубликованном сайте**. Она не спрятана и не
  закрыта паролем — её просто не существует в собранной версии. Поэтому для
  неё не нужен и нигде не хранится ни один пароль или токен.

## Правка с планшета

По умолчанию этот путь **выключен**, и включать его стоит только если очень
нужно. Ниже — что для этого потребуется и чем придётся заплатить.

Редактор из предыдущего раздела работает с файлами на диске, поэтому на
планшете он бесполезен: там нет ни папки проекта, ни терминала. Чтобы править
уроки с планшета, редактор должен ходить в GitHub напрямую, а для этого ему
нужен **персональный токен** — строка, которая даёт право менять ваш репозиторий.

**Чего делать нельзя ни при каких условиях:** класть этот токен в файлы
проекта. Репозиторий публичный, любой токен в нём мгновенно становится
известен всем, и чужой человек сможет менять ваш сайт.

**Как сделать правильно, если решитесь:**

1. На GitHub: **Settings → Developer settings → Personal access tokens →
   Fine-grained tokens**. Создайте токен только для репозитория с сайтом,
   с правом **Contents: Read and write** и сроком жизни в несколько дней.
2. Разверните админку отдельно — на своём компьютере или в закрытом месте,
   не на публичном сайте. Токен вводится в форме каждый раз заново и нигде
   не сохраняется.
3. Когда закончите — **отзовите токен** на той же странице GitHub.

Честно говоря, для разовой правки опечатки проще открыть файл прямо на сайте
GitHub: найти его в репозитории, нажать карандаш, поправить и сохранить.
GitHub сам сделает коммит, и сайт пересоберётся. Токен для этого не нужен —
достаточно войти в свой аккаунт.

## Что делать, если что-то сломалось

### «Проверка не прошла» при публикации

Скорее всего, опечатка в шапке урока. Частые случаи:

| Написано | Как надо | Почему |
|---|---|---|
| `draft: "false"` | `draft: false` | true и false пишутся без кавычек |
| `order: "3"` | `order: 3` | число без кавычек |
| `section: 'Основы'` | `section: 'osnovy'` | нужен id раздела из `src/content/sections.mjs`, а не его название |
| `slug: 'Составные операторы'` | `slug: 'sostavnye-operatory'` | только латиница в нижнем регистре, цифры и дефис |

Сообщение об ошибке всегда называет файл и поле.

### «Два урока с одинаковым order» или «с одинаковым slug»

Два урока претендуют на одно место или один адрес. Поменяйте `order` или `slug`
у одного из них — в сообщении написано, у каких именно уроков конфликт.

### Урока не видно на сайте

Проверьте `draft`. Если `draft: true` — урок специально скрыт, это черновик.
Поменяйте на `false` и опубликуйте заново.

### «GitHub не пустил»

Нужно заново войти в аккаунт GitHub. Проще всего установить
[GitHub CLI](https://cli.github.com) и выполнить `gh auth login`, либо
использовать приложение [GitHub Desktop](https://desktop.github.com).

### «На GitHub есть изменения, которых нет у тебя»

Так бывает, если правили с другого компьютера или прямо на сайте GitHub.
Выполните `git pull --rebase`, потом снова `npm run publish`.

### Сборка на GitHub горит красным

Откройте вкладку **Actions** в репозитории, нажмите на красную строчку и
прочитайте, на каком шаге остановилось. Обычно это то же самое, что показал бы
`npm run publish` у вас на компьютере.

### Совсем непонятно

Выполните `npm run check` и покажите вывод тому, кто настраивал сайт.
Это команда, которая проверяет уроки и код, ничего не меняя.

## Что нельзя класть в репозиторий

Репозиторий публичный. Всё, что в него попало, видно любому человеку в
интернете — и остаётся видно в истории, даже если потом удалить файл.

**Никогда не добавляйте:**

- пароли и токены в любом виде;
- файлы `.env`, `.pem`, `.key`, `id_rsa`, `secrets.*`;
- личные данные учеников: имена, фамилии, классы, телефоны, почту, фотографии;
- скриншоты, на которых видно чужие данные или ваши открытые вкладки с паролями.

Эти файлы уже перечислены в `.gitignore`, а перед каждой публикацией
запускается проверка `npm run check-secrets`, которая ищет в файлах то, что
похоже на токен. Такая же проверка стоит на стороне GitHub. Но проверка —
это страховка, а не разрешение не думать: она знает про распространённые
форматы токенов, а не про всё на свете.

**Если секрет всё-таки попал в репозиторий:** удалить файл недостаточно, он
останется в истории. Считайте секрет скомпрометированным: немедленно отзовите
его там, где выдавали, и выпустите новый.

## Две вещи, которые нельзя починить кодом

Это не недоделки, а свойства выбранного способа публикации. Знать о них надо
заранее.

### 1. Репозиторий публичный, и содержимое доступно всем

Бесплатный GitHub Pages работает только из публичного репозитория. Это значит,
что все файлы курса — тексты уроков, задания, ответы — открыты по адресу
репозитория любому, кто его найдёт. Поисковики их тоже индексируют.

**Если это проблема, есть варианты:**

- **Платный тариф GitHub** (GitHub Pro или Team) — позволяет публиковать Pages
  из приватного репозитория. Сам сайт при этом всё равно остаётся публичным,
  но исходники закрыты.
- **Другой хостинг** — Netlify, Cloudflare Pages и Vercel умеют собирать
  сайт из приватного репозитория бесплатно. Проект собирается обычной
  командой `npm run build` в папку `dist`, поэтому переехать можно без
  переделки.
- **Закрыть сам сайт паролем** — для этого нужен сервер, а у статического
  сайта его нет. Ближайшее решение — Cloudflare Access перед сайтом.

### 2. Ответы к заданиям лежат в исходном коде страницы

Спойлер «Показать ответ» — это обычный раскрывающийся блок. Он сделан так
специально: работает без JavaScript, находится поиском по странице, полностью
раскрывается при печати. Но ответ при этом **есть в коде страницы**, и его
видно, если открыть исходный код или воспользоваться поиском браузера.

Спрятать ответ по-настоящему нельзя: любой способ «подгрузить ответ по
запросу» упирается в то, что подгружать его неоткуда — сервера нет. Шифрование
с ключом в той же странице тоже ничего не даёт, ключ лежит рядом.

**Что можно сделать:**

- **Оставить как есть.** Ребёнок, который целенаправленно лезет в исходный код
  за ответом, точно так же нашёл бы ответ, нажав кнопку.
- **Держать ответы отдельно** — сделать раздел «Для преподавателя» и не
  публиковать его вовсе, а раздавать на занятии.
- **Не давать ответы вообще** для контрольных заданий, а разбирать их вслух.

Изображать, что ответы защищены, не стоит: на статическом сайте это неправда.

|---|---|

## Как устроен проект

```
site.config.mjs              ← адрес сайта. Единственное, что нужно поменять

src/
  content/
    lessons/*.mdx            ← уроки. Один файл — один урок
    sections.mjs             ← список разделов курса
  content.config.ts          ← какие поля обязательны в шапке урока
  components/                ← блоки, из которых состоит урок
  layouts/                   ← общий каркас страниц
  pages/                     ← главная, страница урока, 404
  plugins/                   ← что считается на сборке: номера, оглавление, подсветка
  styles/global.css          ← все стили сайта
  admin/                     ← визуальный редактор, только для локальной работы

public/
  fonts/                     ← шрифты, лежат у нас, а не тянутся из интернета

scripts/                     ← команды npm run …
.github/workflows/           ← что делает GitHub после отправки изменений
```

Два файла остались от разработки и на сайт никак не влияют — их можно удалить:
`urok-sostavnye-operatory.html` (исходный урок, с которого всё началось, уже
перенесён в `src/content/lessons/sostavnye-operatory.mdx`) и `prompt-kurs.md`

### Что сделано ради безопасности и приватности

- Ни одного обращения на чужие адреса: шрифты лежат в проекте, счётчиков,
  аналитики и внешних виджетов нет. Это проверяется при каждой сборке
  на GitHub — сборка упадёт, если что-то появится.
- Никаких форм, никакого сбора данных: сайт ничего не знает о том, кто его открыл.
- Строгая политика безопасности страницы: сторонние скрипты и `eval` запрещены.
- Ввод в тренажёрах только числовой, разметку туда подставить нельзя.
- У GitHub Actions ровно три права: читать код, писать на Pages, подтвердить
  личность при выкладке. Все действия закреплены по номеру коммита, а не по
  подвижному тегу.
- Сайт полностью читается с выключенным JavaScript — не работают только
  тренажёры, и они честно об этом пишут.
